# Parity fixture corpus

**Feature**: `003-pdf-platform-parity` | **Manifest schema**: 1 | **Licence**: MIT

The corpus under `tests/SharpCorePDF.Tests/Assets/parity/` is the evidence the parity matrix in
[`docs/parity.md`](../parity.md) points at. It is **checked in as binary files**: the test suite never
runs Python, `pikepdf`, a network call or a font download. The generator exists so that the bytes can be
reproduced and reviewed, not so that a test depends on it.

* **95 files** in eight groups: 76 PDFs, 14 image/filter fixtures, and 5 labelled JSON expectations.
* **60 born-digital documents** in `corpus/`, five per family: bookmarks, dense text, images, landscape,
  links, metadata, rotated pages, single-column, tables, three-column text, two-column text and Unicode.
* **5 human-labelled reading-order documents** with a JSON expectation beside each PDF.
* **14 image fixtures**, including the formats and variants the contract refuses by name.
* **5 form**, **1 annotation** and **2 signature** fixtures, and **3 PDF/A candidates**.
* Every file is generated by this repository. No third-party PDF, font, image or sample is included.
  The DejaVu subset used elsewhere in the tests is not part of this tree.

## Manifest

[`manifest.json`](../../tests/SharpCorePDF.Tests/Assets/parity/manifest.json) is authoritative. It records, for every file:

| Field | Meaning |
| --- | --- |
| `path` | Path relative to the `parity/` directory. |
| `kind` | `corpus`, `labelled`, `label`, `image`, `form`, `annotation`, `signature` or `pdfa`. |
| `bytes` | Exact byte length on disk. |
| `sha256` | SHA-256 of the file, so a test can detect a changed fixture without regenerating anything. |
| `pages` | Page count for a PDF; absent for an image or a JSON expectation. |
| `features` | The behaviours the fixture exercises, used by the matrix and by the reading tests. |
| `description` | Human description of the document or image. |
| `source` | Always `generated by docs/tools/make-fixtures.py --parity`. |
| `licence` | Always `MIT`. |

Top-level keys repeat the generator, the licence and the coordinate system, and state the provenance in
one sentence: *“Original pages generated by the repository; no third-party PDF, font or image.”*

`manifest.json` itself is not an entry: it is the index, and the test asserts that every entry exists and
that every PDF opens. The fixture tree is copied to the test output by `SharpCorePDF.Tests.csproj`, so a
test reads the same bytes that are in Git.

## Regeneration

From the repository root, with Python 3.11+ and `pikepdf` available (the generator uses `uv` in CI):

```powershell
# Rewrite the checked-in tree in place.
python docs\tools\make-fixtures.py --parity

# Or write a second copy and compare it with the committed tree.
python docs\tools\make-fixtures.py --parity artifacts\parity-regen
git diff --no-index --stat tests\SharpCorePDF.Tests\Assets\parity artifacts\parity-regen
```

The generator is deterministic: fixed dates, fixed identifiers, sorted object order and no timestamps
from the machine. Regenerating the tree must produce an **empty diff**, which is the out-of-test form of
the SHA-256 assertion in `ParityCorpusTests.Every_manifest_entry_matches_its_sha256`.

The generator is split in two for reviewability:

* `docs/tools/make-fixtures.py --parity` is the documented entry point and dispatches to the parity module.
* `docs/tools/make_parity_fixtures.py` holds the page templates, the manifest writer and the feature lists.

## Running the evidence

```powershell
# Corpus integrity, PDF opening, labelled blocks and image refusals.
dotnet test .\tests\SharpCorePDF.Tests\SharpCorePDF.Tests.csproj -p:TargetFramework=net10.0 `
  --filter "FullyQualifiedName~ParityCorpusTests"

# External syntax check on a fixture or an output.
uv run --with pikepdf python docs/tools/validate-pdf.py tests/SharpCorePDF.Tests/Assets/parity/corpus/unicode-01.pdf
```

The parity matrix names the per-capability test and command. This README owns the corpus — provenance,
the manifest contract, regeneration and the integrity test — and the command that scores a reading against
it (below).

## Scoring a reading (SC-004)

SC-004 is measured rather than asserted: `docs/tools/score-layout.py` reads a folder of ALTO exports and
the label files beside the labelled PDFs, and prints one line per threshold. It needs no third-party
package, so a plain `python` runs it:

```powershell
# Score the ALTO exports of the labelled documents; --labels defaults to the checked-in folder.
python docs\tools\score-layout.py artifacts\layout-exports `
  --labels tests\SharpCorePDF.Tests\Assets\parity\labelled `
  --known-order-mismatch table
```

`<exports>` holds one document per label file, named after it: `two-columns.alto.xml` is scored against
`two-columns.json`. Any caller can write that folder — `ExportAsync(..., PdfLayoutFormat.Alto, ...)` is
the whole of it, and the `extract-layout` example writes the same format for its own sample document.

| Measurement | Threshold | What is counted |
| --- | --- | --- |
| Character recall | 99.5% | Characters of the labelled words the read found, matched page by page and word by word. A space has no box of its own in an export, so the recall is over the characters of the words. |
| Box agreement | 95% | Matched words whose four edges are within half a point of the labelled box. |
| Reading order | 95% | Pairs of matched words that sit on different lines on both sides and come out in the labelled order. Words whose line was split or merged carry no evidence and are not counted either way, so the measurement is about order and not about segmentation. |

The `table` document is passed to `--known-order-mismatch` and recorded as a limitation rather than
counted as agreement. A table is symmetric under the XY cut — the gap between its columns is as wide as
the gap between its rows — so a cell becomes a block and the reading order reports a column before the
next column, which is the order a two-column page needs. Telling a table from two columns whose lines
align is a semantic judgement, and table semantics are out of contract. The parity test
`PdfLayoutCorpusTests.Table_page_is_still_read_column_by_column` fails if the limitation ever goes away,
so the exception cannot outlive the behaviour it records.

As measured on 2026-10-22: recall 100% and boxes 100% on all five documents, reading order 100% on four
and 66.7% on `table` (18 of 27 word pairs).

## Licensing and review

The fixtures are original works generated by the repository and are covered by the repository's MIT
licence. A contributor adding a fixture must add it to the generator, regenerate the manifest, and state
its source and licence in the manifest. Third-party sample documents, fonts or images are not accepted
into this tree; if a future fixture needs one, it must carry its own licence file and an explicit entry in
this README before it is committed.
