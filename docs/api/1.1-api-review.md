# Release 1.1 API review

**Feature**: `003-pdf-platform-parity` | **Reviewed**: 2026-10-21 | **Status**: accepted for Phase 1

This is the Phase 0 design review required by T011. It records where the new 1.1 types live, how they are
made immutable, and the checks that keep the dependency and platform rules from drifting while the
creator, editing, reading and trust work lands.

## 1. Surface and placement

The 1.0 layering is kept: **Domain** owns values, plans, read models and ports; **Application** owns the
services that orchestrate a use case; **Infrastructure** owns PDF syntax, file formats and the writer;
**DependencyInjection** only composes the other three. A type that needs to parse a PDF, a font or an
image never enters Domain.

| Area | Domain | Application | Infrastructure |
| --- | --- | --- | --- |
| Geometry and graphics | `PdfPoint`, `PdfMatrix`, `PdfPath`, `PdfPathSegment`, `PdfPaint`, `PdfStroke`, `PdfGraphicsState` | — | `ContentStreamBuilder`, `PathWriter`, graphics-state stack |
| Text layout | `PdfTextStyle`, `PdfTextMetrics`, `PdfTextLayout`, `PdfTextLayoutOptions`, `PdfTextAlignment`, `PdfTextDirection`, `PdfTextOverflow` | — | `PdfTypeface` metrics, `PdfPageCanvas.DrawTextLayout` |
| Images | `PdfImage` metadata value and `PdfImageColorSpace` | — | `PdfImage.Open/FromJpeg/FromPng/FromBmp/FromGif`, `JpegImage`, `BmpImage`, `GifImage`, `PngImage` |
| Editing | `PdfEditPlan`, `PdfEditOperation` variants, `PdfAnnotation`, `PdfForm`, `PdfFormField`, `PdfFormFieldKind` | `PdfDocumentEditorService` (existing service, extended operations) | `PageOperations`, `OverlayWriter`, `IncrementalWriter`, `AnnotationWriter`, `AppearanceStreams`, `AcroFormWriter` |
| Reading | `PdfLetter`, `PdfHyperlink`, `PdfPageSegment`, `PdfObjectView`, `PdfContentOperationView`, the word/segmentation/order enums | `PdfLayoutReaderService`, `PdfObjectInspectorService` | `LetterExtractor`, `LayoutAnalysis/`, `ObjectGraphView`, `Exporters/` |
| Trust | `PdfSignatureOptions`, `PdfSignatureInfo`, `PdfSignatureValidation`, `PdfSignatureProblem`, hash/trust enums, `PdfAProfile`, `PdfAConversionResult` | `PdfSignerService` | `CmsSignatureWriter`, `SignatureFieldWriter`, `TimestampEmbedder`, `SignatureValidator`, `TrustEvaluator`, `PdfAWriter` |
| Ports | `IPdfLayoutReader`, `IPdfObjectInspector`, `IPdfSigner`, `IPdfTimestampProvider` | — | implementations above |

The data model's `PdfImageSource` is realised as the public `PdfImage` in Infrastructure, because opening
a PNG, JPEG, BMP or GIF is format parsing. `PdfPageCanvas.DrawImage` accepts `PdfImage`, a JPEG stream or
the existing `byte[]` overload; no encoded file bytes are copied into a Domain type. The same rule keeps
`PdfTypeface` in Infrastructure: font parsing is not a Domain concern.

## 2. Immutability and the public graph

The reviewed rules are:

1. Every new value and plan is a `sealed record` (or a closed hierarchy of records) with `init`-only
   properties. A `With…`/`Add…` method returns a new instance; the 1.0 `PdfEditPlan` is the pattern.
2. A collection is exposed as `IReadOnlyList<T>` or `IReadOnlyDictionary<K,V>` and is backed by an array
   or a `ReadOnlyCollection<T>` created at construction. No public `List<T>`, `Dictionary<K,V>`, array
   property or settable collection is added. An `IReadOnlyList<T>` is an accidental-mutation guard, not a
   security boundary; the concrete backing store stays private.
3. Bytes are exposed as `ReadOnlyMemory<byte>` (the 1.0 `PdfEmbeddedFileInfo.Data` and `PdfImageInfo.Data`
   already do this), never as a mutable `byte[]` property.
4. Read models have no `Stream`, no `Pdf`/`PdfObject` syntax object and no callback that could mutate a
   source. `PdfObjectView` and `PdfContentOperationView` copy scalar values and child views into their own
   arrays; a dangling reference stays visible as a view with a warning, not as a live indirect object.
5. `PdfSignatureOptions.Certificate` is a reference to a caller-owned `X509Certificate2`. The library
   reads it during signing and never disposes it, stores it in a static, or exposes its private key.
6. A validation method returns `IReadOnlyList<string>` and has no side effect; the checked exception is
   thrown only when a service applies the plan. This keeps `Validate()` usable before a source is opened.

## 3. Naming and signatures

| Rule | Example |
| --- | --- |
| Public types carry the `Pdf` prefix unless they describe a plan or a service. | `PdfPoint`, `PdfLetter`, `PdfEditPlan`, `PdfLayoutReaderService` |
| Options are `…Options`; outcomes are `…Result`; read-only snapshots are `…Info`; write models are `…` without a suffix. | `PdfSignatureOptions`, `PdfEditResult`, `PdfAnnotationInfo`, writable `PdfAnnotation` |
| Closed choices are enums or a sealed record hierarchy, never a stringly-typed property. | `PdfAnnotationKind`, `PdfFormFieldKind`, `PdfTextDirection` |
| Asynchronous methods end in `Async`, take a `CancellationToken` last, and use `ConfigureAwait(false)` in Infrastructure. | `ReadLayoutAsync(source, options, cancellationToken)` |
| An ordered collection says so. Page references are one-based in the API, as in the 1.0 plan. | `IReadOnlyList<PdfLetter> Letters`; `RotatePage(1, …)` |
| A recoverable loss is a `PdfWarning` with a `PdfWarningKind`; a refusal is a typed exception, not `false`. | `ImageFilterUnsupported`, `PdfUnsupportedFeatureException` |

The read model `PdfAnnotationInfo` stays as it is; the writable model is `PdfAnnotation`, so an existing
caller cannot accidentally pass a read snapshot to an edit operation. The same split applies to
`PdfFormFieldInfo` (read) and `PdfFormField` (write).

## 4. Dependencies and platform

The Phase 0 check is deliberately mechanical, and was run on 2026-10-21:

```powershell
dotnet list src\SharpCorePDF.Infrastructure\SharpCorePDF.Infrastructure.csproj package --include-transitive
Get-ChildItem src -Recurse -Filter *.cs |
  Select-String -Pattern 'System.Drawing|SkiaSharp|PdfSharp|PdfPig|HttpClient|WebRequest|Socket'
```

**Result**: Domain, Application and Infrastructure have **no package reference** other than the
`Microsoft.CodeAnalysis.PublicApiAnalyzers` and `SonarAnalyzer.CSharp` analyzers (both `PrivateAssets=all`).
The only third-party packages in the product are the existing
`Microsoft.Extensions.Configuration.Binder`, `DependencyInjection.Abstractions` and `Options` references in
the DependencyInjection project, which predate 1.1. The source search returns **zero** matches for
`System.Drawing`, `SkiaSharp`, `PdfSharp`, `PdfPig`, `HttpClient`, `WebRequest` or `Socket`.

The 1.1 additions therefore use only the base class library: `System.Security.Cryptography` and
`System.Security.Cryptography.Pkcs` for CMS, `System.Xml` for ALTO/PAGE XML, `System.IO.Compression` for
Flate, and the existing PDF writer. No native library, platform binary or font is loaded. The library opens
no socket; a timestamp is a caller-supplied callback and a certificate is a caller-supplied object. System
fonts are never enumerated: a `PdfTypeface` is always built from caller bytes.

## 5. Compatibility with 1.0

1. No existing public signature is removed, renamed or given a different meaning. New operations are
   additive overloads or new types; `IPdfDocumentEditor` keeps its two methods.
2. Existing read results gain only optional, additive properties with defaults, so a 1.0 caller compiles
   unchanged and a missing value is `null` or an empty collection.
3. `PdfEditPlan` remains the only edit aggregate. The new operations are records in the existing closed
   hierarchy, validated in `Validate()` in plan order.
4. The full-rewrite writer stays the default; the incremental writer is opt-in through output options, so
   a caller that needs signatures asks for the revision-preserving path explicitly.
5. Every new public member is added to the layer's `PublicAPI.Unshipped.txt` in the same commit. T097 adds
   a contract test that fails when a public member is missing from that file.
6. Both `net10.0` and `net11.0` are built and tested; a type that only exists on one target is not added.

## 6. Decisions recorded by this review

* **Image factory location** — `PdfImage` and its format parsers live in Infrastructure; Domain receives
  only metadata and decoded pixel data. This resolves the data model's `PdfImageSource` name in favour of
  the plan's `PdfImage` factory without putting file parsing in Domain.
* **Annotation and form naming** — writable `PdfAnnotation`/`PdfFormField` are distinct from the existing
  read-only `PdfAnnotationInfo`/`PdfFormFieldInfo`; no existing read model becomes mutable.
* **Credential ownership** — the caller owns and disposes the certificate and supplies the timestamp
  callback; the library never persists either.
* **No execution** — action dictionaries may be copied or refused with a warning, but no JavaScript, `/AA`
  action or external process is executed by any read or edit path.
* **Refusal over silent loss** — an unsupported image filter, font, colour space or signature algorithm
  produces a named warning or a typed exception; a profile is never labelled PDF/A when a requirement is
  unsatisfied.

## 7. Review gates

A pull request that adds a 1.1 public type must show all of the following in its description:

- the type's layer and why it cannot live in a lower layer;
- its construction and validation rules, and the test that fails on an invalid value;
- the `PublicAPI.Unshipped.txt` entry for every target;
- no new package and no forbidden namespace (the two commands in §4);
- a mutation test or assertion for every read-only collection or view it exposes.

The API is accepted for Phase 1 on that basis. This review does not approve any later signature change;
such a change needs an amendment here and a note in `CHANGELOG.md`.
